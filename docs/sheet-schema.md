# 홍보 사이트 시트 명세

> Google Sheets **1개**. 관문(Apps Script)이 이 시트에 붙어 있다. 공유하지 않으며 관문을 통해서만 쓴다.
> 아카이빙 시트와 별개다(`docs/decisions.md` 3절).

---

## 1. 확정 사항

| 항목 | 규칙 |
|---|---|
| 시트 | 1개 (관문이 붙어 있는 시트) |
| 탭 | 읽어보기 · 공지 · 갤러리 · 첨부 · 접근코드 · 설정 · 로그 · 언론홍보 · 표지 (언론홍보 · 표지는 2026-10-14 추가 — 이미 있는 시트에서는 `setup()`이 맨 뒤에 붙임) |
| 입력 | 공지 · 언론홍보 · 갤러리 · 표지 · 첨부는 **관리자 페이지에서만** 쓴다. 시트에서 직접 고치지 않는다 |
| 글ID | 자동 생성. 공지 `N-0001`, 언론홍보 `P-0001`, 갤러리 `G-0001` (앞자리로 게시판을 구분). 표지는 고정 칸 `H-dance` · `H-music` · `H-art` · `H-trad` |
| 공개여부 | 공개 · 비공개 |
| 공개 파일 | `data/posts.json` (3절) — 공개 글만 담아 관문이 저장소에 커밋 |

## 2. 탭

| 탭 | 입력 | 역할 |
|---|---|---|
| 읽어보기 | 안내 | 시트를 직접 고치지 말라는 안내, 탭 설명 |
| 공지 | 관리자 페이지 | 공지 한 건이 한 줄 |
| 갤러리 | 관리자 페이지 | 앨범 한 개가 한 줄 |
| 언론홍보 | 관리자 페이지 | 기사 한 건이 한 줄 (2-7) |
| 표지 | 관리자 페이지 | 분야 칸 하나가 한 줄, 4줄 고정 (2-8) |
| 사진 | 관리자 페이지 | 사이트 사진 자리 하나가 한 줄, 30줄 고정 (2-9, 2026-11-04) |
| 모집요강 | 관리자 페이지 | 연도 하나가 한 줄 — 글ID `R-0001` · 연도(네 자리, 같은 연도 한 줄) · 제목(선택) · 공개여부 · 작성자 · 시각. 파일은 「첨부」(구분 `파일`, 최대 5개). 관문이 첫 목록 때 만든다. `data/posts.json`의 `guides`: 공개이고 파일이 있는 연도만 `{ "2026": { title, files:[{ fileId, name, size }] } }` (2026-11-04 WBS 17.4) |
| 페이지 | 페이지 직접 편집 | 페이지 하나가 한 줄 — 고친 글자 · 목록(JSON). 처음 저장할 때 관문이 만든다 (2-10, 2026-11-04 WBS 18) |
| 첨부 | 관리자 페이지 | 사진 · 파일 한 개가 한 줄. 글ID로 공지 · 갤러리 · 표지 · 사진 자리와 연결 |
| 접근코드 | 직접 | 운영진 한 사람당 한 줄 |
| 설정 | 직접 | 항목-값. 분류 목록, 실패 제한 등 |
| 로그 | **자동** | 로그인 · 저장 · 삭제 · 업로드 · 발행 기록 |

**탭 이름과 열 이름은 함부로 바꾸지 않는다.** 관문은 탭과 열을 이름으로 찾는다(아카이빙에서 탭 이름을 바꿔 로그인이 전부 멈춘 사례가 있음).

### 2-8. 표지 (2026-10-14)

| 열 | 값 | 비고 |
|---|---|---|
| 글ID | `H-dance` · `H-music` · `H-art` · `H-trad` | `setup()`이 4줄을 만든다. 새로 만들거나 지우지 않는다 |
| 칸 | `무용` · `음악` · `미술` · `전통예술` | 관리자 화면 표시용 |
| 작성자 · 작성시각 · 수정자 · 수정시각 | | 자동 (작성자 · 작성시각은 빈칸으로 남음) |
| 입체효과 | `예` · 빈칸 | 2.5D 입체 효과를 켰으면 `예` (2026-10-15 추가 — 이미 있는 탭에는 `setup()`이 맨 뒤에 붙임) |
| 입체중심 | `62.7,55.3` · 빈칸 | 확대 중심(사진 가로 · 세로의 %). 관리자 화면이 누끼의 인물 영역을 감싸는 상자의 가운데로 계산. 누끼가 없으면 빈칸 |

- 사진은 「첨부」에 글ID `H-…`로 **한 장만** 붙는다. 바꾸면 예전 사진은 휴지통으로.
- 2.5D를 쓰는 칸은 누끼(구분 `누끼`)도 한 장 붙는다. 입체효과가 `예`이려면 누끼가 있어야 하고 원본과 크기가 같아야 한다. **원본을 빼거나 바꾸면 누끼도 휴지통으로 가고 입체효과가 꺼진다** (2026-10-15 사용자 결정). 입체효과를 끄기만 하면 누끼는 남는다.
- **동영상** (2026-10-16 2안, 열 추가 없음): 칸마다 동영상(구분 `동영상`)을 한 개 붙일 수 있다. 사진은 그 칸의 **대기 사진**이 되고(관리자 화면이 영상 첫 장면을 잘라 자동으로 바꿈) 꼭 있어야 한다. 동영상 칸은 2.5D를 쓰지 않는다(입체효과가 `예`면 저장 거절).
  - 드라이브 영상은 다른 사이트의 `<video>`에서 재생되지 않아(2026-10-16 시험), 영상은 **영상 전용 공개 저장소**(Script Properties `MEDIA_REPO`, 기본 `kartsgifted/home-media`, GitHub Pages)의 `hero/{첨부ID}.mp4`로 **저장할 때** 커밋한다. 올리기만 하고 저장하지 않은 영상은 드라이브(공유 안 함)에만 있다.
  - 동영상을 빼거나 바꾸면 저장소에서 지우고 드라이브 조각은 휴지통으로. **저장소 이력에는 남는다** — 완전히 지우려면 그 저장소의 이력을 정리하거나 저장소를 새로 만든다.
  - 동영상을 모르는 화면(1안 관리자 페이지)이 저장하면(`videos`를 보내지 않음) 기존 동영상을 두되, 사진을 빼거나 2.5D를 켜면 뺀다.
- 표지는 이 순서(무용 → 음악 → 미술 → 전통예술)로 넘어간다. 사진이 없는 칸은 사이트의 기본 사진(`main.css --img-hero-*`)을 쓰고, 기본 사진도 없으면 건너뛴다.

### 2-9. 사진 (2026-11-04, WBS 15)

표지 · 공지 · 갤러리 밖에서 페이지에 박혀 있던 사진(메인 여정 3장 · 모집 띠, 하위 페이지 위 사진 띠 5곳, 사업소개 네 분야 4장, 워크숍 카드 17장)을 관리자 페이지 「사이트 사진」 탭에서 바꾼다.

| 열 | 값 | 비고 |
|---|---|---|
| 글ID | `S-step1` · `S-recruit` · `S-sv-about` · `S-ab-dance` · `S-mu1` · `S-da3` … (30개) | 목록은 관문 `apps-script/Photos.js` `PHOTO_SLOTS_`. **관문이 만든다** — 새로 배포한 뒤 처음 목록을 열 때(또는 `setup()`) 탭 · 빠진 행을 만든다. 새로 만들거나 지우지 않는다 |
| 칸 | `메인 · 여정 01 워크숍` 등 | 시트를 읽는 사람용. 관리자 화면은 `admin.js` `PHOTO_PAGES`의 이름을 쓴다 |
| 위치 | `30.0,70.0` · 빈칸 | 보이는 위치(사진 가로 · 세로의 %) — 화면의 `object-position` · `background-position`. 빈칸이면 올린 사진은 가운데, 기본 사진은 페이지에 적힌 기본 위치 |
| 작성자 · 작성시각 · 수정자 · 수정시각 | | 자동 (작성자 · 작성시각은 빈칸으로 남음) |

- 사진은 「첨부」에 글ID `S-…`로 **한 장만** 붙는다(긴 변 2400px로 줄여 올림). 바꾸거나 빼면 예전 사진은 휴지통으로. 빼면 페이지의 기본 사진(HTML · CSS에 적힌 것)으로, 기본 사진이 없는 워크숍 카드는 「사진 준비 중」으로 돌아간다.
- 사진 없이 위치만 저장하면 기본 사진의 보이는 위치만 바뀐다.
- 자리를 늘리거나 페이지 구조를 바꾸면 세 곳을 함께 고친다: `Photos.js` `PHOTO_SLOTS_` · `admin.js` `PHOTO_PAGES`(기본 사진 · 기본 위치 · 화면 비율) · 페이지의 `data-photo`.

- 페이지 직접 편집(WBS 18)에서 사진이 있는 목록 항목을 복제하면 새 자리 `S-{원래 자리}-x{4자}`가 생긴다. 처음 사진을 넣을 때 관문이 행을 만들고 「칸」에 `페이지 편집 · {원래 칸} (복제)`를 적는다. 관리자 페이지 「사이트 사진」 탭에는 나오지 않는다(화면에서 고침). 항목을 지워도 행은 남는다(사이트에는 영향 없음).

### 2-10. 페이지 (2026-11-04, WBS 18)

운영진이 사이트 화면 위에서 고친 글자 · 목록 항목. 공개 사이트에 그대로 나가는 고정 문구라 공개여부가 없다.

| 열 | 값 | 비고 |
|---|---|---|
| 페이지 | `index` · `about` · `recruit` · `programs` · `mentoring` · `camp` · `news` | 한 페이지 한 줄 |
| 내용 | `{"t":{"k5":"고친 글"},"l":{"l2":[{"s":1},{"s":0,"t":{"1":"음악"},"p":"ab-music-x4k2"}]}}` | **직접 고치지 않는다.** 깨지면 그 페이지는 HTML 글 그대로 보인다 |
| 수정자 · 수정시각 | | 자동 |

- 열쇠는 HTML에 붙어 있다: 글자 칸 `data-e="k5"`, 목록 `data-list="l2"`, 목록 항목 안 글자 칸 `data-ei="1"` (`docs/tools/annotate-edit.py`가 붙임). **이미 붙은 열쇠를 바꾸거나 지우면 그 칸의 고친 글이 다시 들어가지 않는다.** 문장을 더했으면 스크립트를 다시 돌려 새 칸에만 다음 번호를 붙인다.
- `t`: 고친 칸만. 칸 값은 글(`**굵게**` · `==형광==` · 줄바꿈 `\n`만 쓴 칸) 또는 글쓰기 도구의 `{ "r": [조각], "a": "c" }`(조각 = `{x, b, i, u, m, s, c, f, h}`, 정렬 `a`: l · c · r — 2026-11-05). 목록 항목 · 더한 문단 · 더한 구역의 칸도 같다.
- `l`: 바꾼 목록만, 화면 순서대로. `s` = HTML의 몇 번째 항목을 본떴는지(0부터), `t` = 그 항목 안에서 고친 칸, `p` = 복제한 항목의 사진 자리(2-9).
- `a`: 더한 문단 `{ "k5": ["문단", …] }` — 글자 칸 k5(문단 p) 바로 뒤에 같은 모양으로 (WBS 18.7).
- `x`: 더한 구역 `{ "s4": [ { "k", "h", "d", "p", "i", "ph" }, … ] }` — 구역 자리 `data-sec="s4"` 바로 뒤에, 적힌 순서대로. `k`: `text`(제목 + 글) · `photo`(제목 + 사진 + 글) · `table`(제목 + 표) · `cards`(제목 + 카드) · `steps`(제목 + 단계), `h` 제목, `d` 제목 밑 설명(없으면 뺌), `b` 글쓰기 도구의 문단들(text · photo — 소제목 · 목록 가능, 2026-11-05. 예전에 저장한 `p` 문단 목록도 읽음), `i` `[제목 · 항목, 설명 · 내용]` 목록(table · cards · steps), `ph` 사진 자리 `sec-x4자`(photo — 사진은 「사진」 탭 `S-sec-x4자`, 2-9).
- HTML에서 목록 항목을 빼거나 순서를 바꾸면 `s`가 다른 항목을 가리키게 되니, 그때는 그 페이지 줄을 확인한다(확인 필요 시 개발자).

| 표지 동영상 | `heroVideo`는 동영상을 올린 칸만 `{ src: 영상 저장소 경로, w, h }` (2026-10-16 2안). 그 칸의 `hero`에는 대기 사진(첫 장면)이 그대로 있어, `heroVideo`를 모르는 1안 화면은 사진을 보인다. 주소 앞부분(`https://kartsgifted.github.io/home-media/`)은 화면(`main.js` · `admin.js`의 `MEDIA_BASE`)이 붙인다. 동영상이 없으면 `{}` |

| 페이지 글 | `pages`는 「페이지」 탭에서 내용이 맞는 페이지만 (2026-11-04 WBS 18, 2-10). 화면 `assets/js/content.js`가 HTML 글 위에 넣는다. 없는 페이지는 HTML 그대로 |
| 필드명 | 시트 열(한글)을 영어 camelCase로 옮긴다. `photoPosition`은 `top` · `bottom` |
| 갤러리 과정 · 분야 | `course` · `field`는 늘 들어간다 (2026-10-16 2안 WBS 8.10, 1안 화면은 이 값을 쓰지 않는다). `course`: `workshop` · `mentoring` · `camp` · `""`(지정 안 함). `field`: `dance` · `music` · `art` · `trad` · `""`(그 과정 공통, 또는 지정 안 함). 시트 값이 빈칸이거나 목록에 없으면 둘 다 `""`. 8.5 때는 `field` 하나에 `mentoring` · `camp`도 들어갔으나 이제 그 값은 `course`로 간다. 프로그램 페이지: 워크숍 분야 탭은 `course=workshop`이고 `field`가 그 분야이거나 `""`인 앨범, 심화 멘토링 · 겨울캠프는 그 `course`의 앨범 모두 |
| 빈 값 | 사진 · 파일이 없으면 빈 배열, 본문 · 링크가 없으면 빈 문자열 |
| 파일이 없을 때 | 화면은 "등록된 글이 없습니다"를 보인다 (발행 전 첫 배포 상태) |

## 4. 업로드 규칙

| 항목 | 사진 | 파일 |
|---|---|---|
| 형식 | jpg · png · webp (올리기 전에 JPEG로 변환. 표지 누끼는 png · webp를 받아 PNG로 둠) | hwp · hwpx · doc · docx · pdf · xls · xlsx · ppt · pptx |
| 크기 | 브라우저가 긴 변 1600px로 줄인 뒤 올림 (표지 사진은 2400px, 누끼는 원본 사진 크기로 맞춤 · 한 개 8MB 이하) | 한 개 10MB 이하 (보통 100~200KB) |
| 개수 | 공지 한 건 10장 · 갤러리 앨범 하나 50장 · 표지 칸 하나 1장(+ 누끼 1장) | 공지 한 건 10개 |

**표지 동영상** (2026-10-16 2안): MP4(H.264)만, 한 개 20MB 이하(`LIMITS_.videoBytes`), 칸 하나에 1개. 줄이거나 바꾸지 않고 그대로 올린다(관리자 화면이 브라우저에서 열어 보고 열리지 않는 영상 — 아이폰 HEVC 등 — 은 거절). 관문 요청 크기 한도 때문에 약 4MB(`LIMITS_.videoPartBytes`, 3의 배수) 조각으로 나눠 올린다. 권장: 10~20초 · 1080p · 가로.

개수 · 용량 한도는 **확인 필요** — 임시값이며 실제 운영 자료를 보고 조정한다.
